## RE-VERIFY GATE

**Three of my own findings killed before surfacing — all three were flat greps misreading JSON-LD nesting.**

**1. "Buda has BreadcrumbList ×2" → initially REJECTED by my own JSON parser, then RE-CONFIRMED as real.**
`grep -c '"BreadcrumbList"'` returned 2. My first parser found only 1 — because it didn't recurse into the
`WebPage.breadcrumb` property. Had I trusted either result alone I'd have shipped the wrong call: the grep
alone gives no idea whether the two are duplicates or one nested reference, and the shallow parse says
"no problem." Only walking the full object graph showed **two trails that genuinely disagree.**

**2. "11 pages use nested `WebPage.breadcrumb`, so Buda is normal" → REJECTED (artifact).**
`grep -l '"breadcrumb"'` matched 11 files. Structured parse: **10 of them have zero nested BreadcrumbList.**
They matched on `<nav class="breadcrumb" aria-label="Breadcrumb">` — a **CSS class**, not schema. This one
nearly inverted the fix: it would have made Buda look like the compliant page and the other 8 look broken.

**3. "Dev commentary is leaking into rendered homepage copy" → REJECTED (my parser, not the page).**
My body-text extractor emitted `...the LCP culprit). -->` inside the first 150 words, which reads exactly
like an unclosed HTML comment shipping to users — a HIGH finding. Live homepage: **42 `<!--` / 42 `-->`,
balanced.** The regex `<[^>]+>` terminates a comment at the first `>` inside it, spilling the rest as text.
The page is fine; my stripper was wrong.

**4. "6/9 suburbs have Person, 3 are missing it" → REFRAMED, and the fix changed completely.**
True but useless. The 6 split into two structurally different constructs — 2 standalone canonical entities
and 4 nested `employee`/`founder` references. A nested employee legitimately may omit `@id`; a standalone
duplicate really should have one. Chasing the flat count would have applied a top-level convention to
nested references. The reframe is also what surfaced the `founder` claim — the single most important find
of the run, which the flat count rendered invisible.

## NOTEBOOK_INSIGHTS (cache for future runs if NotebookLM is down)

- **NEW — for JSON-LD, `grep` counts are not evidence; walk the object graph.** Three separate false
  findings today, all from flat text matching: `"BreadcrumbList"` counted a nested `@type` and a top-level
  node as interchangeable; `"breadcrumb"` matched a **CSS class**; `"Person"` conflated a canonical
  top-level entity with a nested `employee` reference. JSON-LD semantics live in **nesting position**,
  which no flat search can see. Parse, then walk with the parent key in hand.
- **NEW — a true count can still be a useless finding.** "6/9 pages have Person" was accurate and led
  toward the wrong fix. Splitting it by construct (2 canonical / 4 nested / 3 absent) is what surfaced the
  `founder` claim — the most important find of the run, which the aggregate had hidden.
- **NEW — check your own extractor before believing it found a site defect.** A regex HTML stripper
  reported dev commentary rendering to users; the live page had 42/42 balanced comments. `<[^>]+>` ends a
  comment at the first `>` inside it. Distinguish *my tool broke* from *the page is broken* first.
- **NEW — prefer the fix that removes an unsupported claim over the one that adds a claim.**
  `founder` → `employee` was safe precisely because the site already asserted `employee`/`worksFor` on
  77 pages. Adding a Person block to the 3 pages that lack one would have meant inventing property values —
  same "improve the schema" impulse, opposite risk profile.
- **NEW — predict the dirty count before committing in this repo.** 52 → 56 (4 edits) → 52 after commit
  turns "I staged the right files" into a falsifiable check that catches a stray `-A`.
- Check `robots.txt` FIRST on any sitemap-addition candidate — it overrides every other guard.
- The peer-set rule applies to your own writing. n=1 is a hypothesis.
- When the site and a guide disagree, check which one is dated.
- Coverage sweeps must normalize URL form (root and trailing-slash vs `/path.html`).
- An absence is only a defect if the page is actually competing for the query.
- Uniform absence (0/N) is design; outlier absence (1/N) is the defect — but robots.txt can veto even that.
- Sandboxed Bash false-returns HTTP `000` — run curl with the sandbox disabled.
- Foreground `sleep` is blocked — write docs between push and live-verify.
- Netlify strips the `netlify` form attribute at build time — verify form wiring against committed source.
- Quote-agnostic + extensionless greps on live pages — Netlify Pretty-URLs strip `.html`.
