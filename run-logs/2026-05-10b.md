*New methodology learning this run:*
- **In zsh-on-darwin inline-expansion contexts, `curl` may not resolve from $PATH inside heredoc/for-loops invoked via the harness — use absolute `/usr/bin/curl`.** First call this run failed with "command not found" inside the `for path in ...` loop, even though `which curl` returned `/usr/bin/curl` directly. Likely a PATH-stripping or shell-built-in interaction in the eval'd loop. Defensive pattern: `CURL=/usr/bin/curl` at the top of multi-call verification blocks. Sub-second fix once spotted, but worth carrying so future agents don't waste a cycle debugging it.
