## NOTEBOOK_INSIGHTS (cache for future runs if NotebookLM is down)

*New methodology learning this run:*
- **`grep -E "a\|b"` is NOT alternation — `\|` is literal pipe in extended-regex mode.** Today's first conversion-tracking pass returned 0 for `consent\|TCPA` and `netlify/functions/lead-intake\|netlify-lead-intake` — interpreted as missing tokens. Re-running with `grep -E "a|b"` (no backslash) returned the expected 9 and 1. In basic regex (`grep -G` / no `-E`), `\|` IS alternation; in extended regex (`-E`), pipe `|` is alternation and `\|` is literal. The yesterday PM run log used `"consent\|TCPA"` and returned 5 — so the bug was previously silent (maybe `-E` not actually applied? or different grep version behavior). Defensive pattern: standardize on `grep -E "a|b"` for alternation, NEVER `grep -E "a\|b"`. Add to standard conversion-trace fixture.
