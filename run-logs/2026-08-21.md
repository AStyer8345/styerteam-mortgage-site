## RE-VERIFY GATE

**Two of my own false findings killed before surfacing. Both were my tooling, not the site.**

**1. "34 pages have severely truncated meta descriptions" → REJECTED (my regex).**
My extractor was `content=["\'](.*?)["\']` — it opens on a double quote but closes on **either**
quote character, so it terminated at the first apostrophe inside the text. The tell was in the data
itself: every "short" description ended exactly where an apostrophe belongs — *"Underwriters don"*,
*"A lower rate doesn"*, *"Kyle is one of Texas"*, *"Here"*. `index.html` reported a **6-character**
description ("Austin"). Fixed with a backreference so the closing quote must match the opening one:
`content\s*=\s*(["\'])(.*?)\1`. **Real count of severely-short descriptions: zero.**

> Had I trusted this, I would have rewritten **34 working meta tags** to fix a bug in my own regex.

**2. "3 pages still assert Adam is `founder`" → REJECTED (wrong working directory).**
Yesterday's fix took `founder` to 0. My check reported 3. Cause: sandbox-disabled Bash calls reset
cwd, so `grep -l '"founder"' *.html` ran in `/tmp` — which is littered with scratch HTML from previous
runs (`live_buda.html`, `deep404.html`, …). Re-run in the repo with an absolute `cd` and a quoted
glob: **0 `founder`, 16 `employee`, 70 `worksFor`.** Yesterday's fix holds.

> A relative glob is only as good as the cwd you think you're in. This one accused a *fixed* defect of
> being back — the most expensive kind of false positive, because it invites re-fixing working code.

## NOTEBOOK_INSIGHTS (cache for future runs if NotebookLM is down)

- **NEW — a regex that opens on one quote must close on the *same* quote.** `content=["\'](.*?)["\']`
  terminates at the first apostrophe in the text. It manufactured 34 phantom "truncated description"
  findings, including a 6-character homepage description. Use a backreference: `(["\'])(.*?)\1`.
  **The tell was in the data:** every truncation landed exactly where an apostrophe belongs.
- **NEW — sandbox-disabled Bash resets cwd; a relative glob then reads the wrong directory.** A
  `grep '*.html'` intended for the repo ran in `/tmp` and reported a *fixed* defect as back. Always
  `cd` with an absolute path in the same command, and quote globs (`--include='*.html'`) — zsh expands
  them before `grep` sees them.
- **NEW — stop writing scratch files to `/tmp`.** Repo `CLAUDE.md` designates a session scratchpad.
  `/tmp` now holds dozens of stale `.html` files from past runs, and they are live bait for exactly
  the false positive above.
- **NEW — in a repo with an uncommitted overlay, audit `git show HEAD:<path>`, not the working tree.**
  Netlify builds from `main`. Reading local files describes a checkout nobody deployed.
- **NEW — "out of target band" is not the same as "defective."** 57 descriptions sit at 121–149 chars,
  under the 150 target but not truncating and not duplicated. Only the >165 group was actually losing
  text in SERP. Fix the ones that lose information; leave the ones that merely miss a round number.
- **For JSON-LD, `grep` counts are not evidence; walk the object graph.**
- **A true count can still be a useless finding** — split by construct before concluding.
- **Prefer the fix that removes an unsupported claim over the one that adds a claim.**
- **Predict the dirty count before committing in this repo.** 52 → 61 (9 edits) → 52 after commit.
- Check `robots.txt` FIRST on any sitemap-addition candidate — it overrides every other guard.
- The peer-set rule applies to your own writing. n=1 is a hypothesis.
- When the site and a guide disagree, check which one is dated.
- Coverage sweeps must normalize URL form (root and trailing-slash vs `/path.html`).
- Uniform absence (0/N) is design; outlier absence (1/N) is the defect.
- Sandboxed Bash false-returns HTTP `000` — run curl with the sandbox disabled.
- Foreground `sleep` is blocked — write docs between push and live-verify.
