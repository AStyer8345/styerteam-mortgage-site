## NOTEBOOK_INSIGHTS (cached — NotebookLM down 60 runs)

- **Sitemap-lastmod selectivity rule (refined again today).** Of 128 files showing stale lastmod-vs-commit-date, only 3 warranted bumps today. The discriminating question is: "did the touching commit change crawler-meaningful content?" Canonical URL normalization (mechanical), cache-buster bumps (JS asset), and link-href updates (internal-only) do NOT warrant lastmod bumps. Material content rewrites (homepage AEO, scenarios analytics fix), new pages, and dateModified-changing commits DO. Reusable filter: `(adam-committed) AND (content-bearing-change) AND (>12h since commit)` for ZERO_RISK auto-bump scope.
- **Date-prefixed blog URL canonical form catches naive "title-only" URL guesses.** Sunday's run log recorded the physician post URL as `/blog/physician-mortgage-texas.html` (title-only). Today the actual canonical URL was `/blog/2026-05-30-physician-mortgage-texas.html` (date-prefixed). The 404 was a documentation defect, not a regression. Reusable rule: when verifying a blog post URL across runs, NEVER reconstruct from the title — always check the sitemap.xml entry or the blog.html manifest to get the canonical filename. The two-step (extract filename from sitemap, then curl) is 1 grep + 1 curl, costs nothing, eliminates the wrong-URL false-404 class entirely.
- **JSON-LD parse via Python is the right schema audit instrument.** Today's homepage + about audit used `re.findall + json.loads` to extract every `application/ld+json` block, then iterated `@type` / `name` / `address.streetAddress`. Single-pass, exact-state, catches issues that grep misses (e.g., type subclass mismatches like MortgageBroker vs LocalBusiness, address-field divergence within same-page schemas). Naive `grep -c '"@type": *"MortgageBroker"'` returned 2 on homepage (parse confirms only 1 — the grep was double-matching across multi-line schema). The Python-parse path is the canonical Monday Rich-Results audit toolkit; the grep path is unreliable when schema spans multiple lines. Added to Monday rotation canonical.
- **GOALS.md "no new content" + GOALS.md "Phase A repositioning" are not in tension — the rule is mechanical/compliance-only edits.** Today's sitemap lastmod bump is metadata/compliance, fits cleanly inside GOALS.md scope. Adding new suburb city-page content (in the seo-sem backlog) does NOT fit — even though it's LOW_RISK and the agent rules allow it. Reusable principle: when the GOALS.md says "no new content beyond X", check every backlog item against that scope before treating it as auto-actionable. Most LOW_RISK items in the backlog this run failed the GOALS.md scope check (city-page enrichment, new blog posts) — correctly skipped.
